# 디지털 기초 수업 실습 앱

발달장애 성인 대상 **인공지능 수업**에서 학생들이 각자 노트북으로 직접 실습하는 웹앱입니다.

수업의 본론은 **3·4차시(AI가 배우는 방법 / AI와 대화)**입니다. 학습자들이 컴퓨터 조작 자체를
어려워해서 1·2차시(전원·마우스·키보드)를 준비운동으로 앞에 두었습니다.
5차시부터는 **진짜 AI**로 넘어가, 낱말 카드로 부탁하는 말을 만들어 그림을 받아옵니다.

- **학생 접속 주소**: https://hyunminju.github.io/digitalbasic/
- 차시별 단일 HTML 파일, 외부 라이브러리 없음, 인터넷만 되면 어떤 브라우저에서든 동작
- 접속하면 차시 선택 화면(`index.html`)이 나오고, 거기서 1~5차시를 고른다

> **파일 번호와 실제 회차가 다릅니다.** 실제 수업에서는 1차시에 `lesson1`,
> **2차시에 `lesson2`+`lesson3`+`lesson4`를 몰아서** 진행했습니다.
> 그래서 `lesson5`는 **실제 수업으로는 3차시**입니다.

## 1차시 — 컴퓨터와 친해지기 (`lesson1.html`)

| 모듈 | 단계 |
|---|---|
| ⏻ 전원 켜고 끄기 (7단계) | 전원 버튼 찾아 누르기 → 부팅 기다리기 → 바탕화면 알기 → "끌 때는 화면에서!" 개념 → 시작 버튼 → 전원 → 시스템 종료 |
| 🖱️ 마우스 연습 (8단계) | 역할 소개 → 별에 올리고 3초 기다리기 → 클릭 → 더블클릭(선물 열기) → 오른쪽 클릭(비밀 메뉴) → 스크롤(꿀벌 옮기기) → 드래그(과일 4개) → 자유 연습장 |
| ⌨️ 키보드 연습 (5단계) | 역할 소개 → 아무 키나 눌러보기 → 스페이스 → 엔터 → 내 이름 첫 글자 자유 놀이 |

세 모듈을 모두 완료하면 "오늘 공부 다 했어요! 🎓" 축하 화면이 나옵니다.

## 2차시 — 키보드와 친해지기 (`lesson2.html`)

화면 키보드에서 목표 키가 파랗게 반짝이면, 실제 키보드에서 같은 자리를 찾아 누른다.
"화면 ↔ 실물 대응" 한 가지 기술에 집중한다. 두 파트로 나뉜다.

| 파트 | 단계 |
|---|---|
| 🔍 키보드 위치 찾기 (13단계) | 소개 → 스페이스·엔터 → 가운데줄(ㅏㅇㄴ) → 윗줄(ㄱㅂ) → 아랫줄(ㅡㅊ) → 숫자(1·5·0) |
| ✍️ 글자 따라 쓰기 (10단어) | 소개 → 가·누·말·벗·아가·도리 → 나무·사람 → 고양이 → 대한민국 |

**따라 쓰기 동작**: 목표는 완성된 글자(`도리`)로 보여주고, 아래 작은 자모열(`ㄷ ㅗ ㄹ ㅣ`)이 누르는 순서를 안내한다.
입력칸은 치는 대로 실시간 조합된다(`ㄷ` → `도` → `도리`). 잘못 누른 글자는 **빨갛게 남고**, 이때 키보드에서
**지우기 ⌫ 키가 반짝여** 지우도록 안내한다. 목표와 정확히 일치해야 다음으로 넘어간다.

> 단어 추가 시 주의: 화면 키보드에 복합모음(ㅘㅙㅚ…)과 된소리(ㄲㄸㅃ…)가 없고 Shift도 쓰지 않는다.
> `사과`·`코끼리` 같은 낱말은 조합이 깨지므로 **단자음+단모음** 낱말만 쓸 것.

## 3차시 — AI는 어떻게 배울까요? (`lesson3.html`)

"정답을 알려주는 학습"과 "정답 없이 비슷한 것끼리 묶는 학습"의 차이를 직접 겪어 본다.
세 파트로 나뉜다.

| 파트 | 단계 | 사진 |
|---|---|---|
| 🏷️ 정답을 알려주며 가르치기 (지도학습) | 소개 → 강아지만 고르기 → 고양이만 고르기 → 정리 | 🐶🐱 강아지·고양이 8장 |
| 🧩 비슷한 것끼리 모으기 (비지도학습) | 소개 → 8장을 두 무리로 나누기 → 정리 | 🐰🐹 토끼·햄스터 8장 |
| ⚖️ 두 가지를 비교해요 | 소개 → 지도/비지도 비교표 → 무엇을 보고 나눴나(복수 선택) → 정리 | — |

**두 파트에 서로 다른 동물을 쓴다.** 같은 사진을 다시 쓰면 지루하기도 하지만, 더 큰 문제는
학습자가 앞에서 낸 답("강아지 여기, 고양이 저기")을 그대로 되풀이해서 정작 *비슷한 점 찾기*를
안 하게 된다는 점이다.

**사진은 일부러 애매하게 만들었다.** 두 세트 모두 종류와 털색(밝음/어두움)이 교차하도록
생성해서, 학습자가 *종류로도* *색깔로도* *자세로도* 나눌 수 있다. 그래야 비지도학습이
"정답 맞추기"가 되지 않고, 마지막 "어떤 특징을 보았나요?" 질문과 **"사람마다 중요하게 본
특징이 다를 수 있어요"**라는 마무리가 살아난다.

> 비지도학습 화면에서는 정답이 새지 않는다 — 이름표도, 대체 텍스트("동물 사진 3")도,
> 파일 이름(`un01.jpg`)도 종류를 드러내지 않는다.

**나누는 방법 두 가지** — 사진을 아래 무리로 **끌어다 놓거나**, 그냥 **눌러서** 나오는
버튼으로 고른다. 드래그는 손 움직임이 불편하면 어려우므로 누르기를 반드시 함께 둔다.
12px 미만으로 움직이면 손떨림으로 보고 클릭으로 처리한다.

> 사진(`images/`)을 못 불러와도 이모지 카드로 자동 대체되어 실습이 끊기지 않는다.

## 4차시 — AI와 이야기 나누기 (`lesson4.html`)

AI와 대화하는 방법을 익히고, AI가 **어떻게 답을 고르는지**까지 눈으로 본다.

| 파트 | 단계 |
|---|---|
| 💬 대화창 사용해 보기 | 소개 → 문장 골라 보내기 → 빈칸 채워 보내기 → 정리 |
| 🔍 AI는 무엇을 보고 답할까 | 소개 → 낱말 반짝임·되물음에 대답하기 ×2 → 정리 |
| 🤔 AI도 모를 때가 있어요 | 소개 → 모르는 말 보내 보기 → 정리 |

**"쓰기 → 보내기"가 두 동작이라는 걸 익히는 게 1파트의 핵심입니다.** 문장 카드를 눌러도
전송되지 않고 입력칸에 들어가기만 하며, `📨 보내기`를 눌러야 전송됩니다.

**AI가 붙잡은 낱말을 노랗게 보여줍니다.** "오늘 **날씨** 어때요?"를 보내면 `날씨`가
반짝이고 "「날씨」라는 낱말을 보고 답을 골랐어요"라고 알려줍니다. 3차시에서 배운
"AI는 반복되는 특징을 찾는다"가 낱말에서도 똑같이 작동한다는 걸 잇는 지점입니다.

**대화가 주고받기로 이어집니다.** AI가 답하면서 되묻고, 그러면 문장 카드가 **그 질문의
대답으로 바뀝니다.**

> 학생: 이름이 뭐예요?
> AI: 저는 컴퓨터 친구예요. 아직 이름이 없어요. **저한테 이름을 지어 주실래요?**
> *(카드가 [하늘이] [별이] [토토] 로 바뀜)*
> 학생: 하늘이
> AI: 우와, 마음에 들어요! 이제 그게 제 이름이에요.

이때 "AI가 **제 이름**을 물어봤죠? 그걸 **기억하고** 대답을 받았어요"라고 설명해서,
AI가 앞말을 기억한다는 것까지 보여줍니다. 같은 주제를 다시 꺼내면 "아까도 그 이야기를
했죠?"처럼 표현을 바꿔 답합니다.

3파트에서는 **AI가 모른다고 답하는 모습**을 보여줍니다. AI 말이 항상 맞는 건 아니라는
태도를 함께 가르치기 위해서입니다.

> **API를 쓰지 않습니다.** 학생들이 각자 노트북으로 접속하는데, 정적 사이트에 API 키를
> 넣으면 F12로 바로 노출되고 소스도 공개라 누구나 키를 가져가 요금이 청구됩니다.
> 게다가 진짜 AI는 속을 볼 수 없어서 "원리 가르치기"라는 목표 자체를 이룰 수 없습니다.
> 답변은 낱말 규칙표(`RULES`)로 정해집니다 — 일부러 단순하게 두어야 원리가 보입니다.

> 입력은 **화면 자모 키보드**로 합니다. 진짜 입력칸을 쓰면 한/영이 영문일 때 `날씨` 대신
> `skfTl`가 찍히고 학생은 이유도 모른 채 막힙니다. 2차시와 같은 방식입니다.

## 5차시 — AI에게 그림 부탁하기 (`lesson5.html`)

**타이핑을 하지 않습니다.** 학생들이 문장 치기를 힘들어해서, 이 차시부터는 **낱말 카드를 눌러**
부탁하는 말을 만듭니다. 만든 말을 **복사 → 붙여넣기**로 옮기는 것이 이번 시간의 새 기술이고,
마지막 파트에서는 그걸 **진짜 제미나이**에 넣어 진짜 그림을 받아 옵니다.

| 파트 | 칸 | 단계 |
|---|---|---|
| 📋 연습해 보기 | 2칸 | 소개 → 말 만들어 복사·붙여넣기 ×3 → 정리 |
| 🌈 자세히 말하기 | 3칸 | 소개 → 색·모습·움직임을 붙여 말 만들기 ×3 → 정리 |
| 🤖 진짜 AI에게 부탁하기 | 3칸 | 소개 → 말 만들어 복사 → 제미나이에서 Ctrl+V → 정리 |

**말이 자랍니다.** 처음엔 「고양이 / 그림 그려 줘」 두 칸이고, 다음 파트에서 앞에 한 칸이
붙어 「점프하는 / 곰 / 그림 그려 줘」가 됩니다. **조작은 똑같고 칸만 하나 늘어서**
학생이 새로 배울 것이 없습니다. 다음 차시부터는 칸이 더 늘어납니다.

> 90분에 세 파트가 빠듯하면 **「자세히 말하기」를 건너뛰어도 됩니다.**
> 홈에서 파트를 골라 들어가고, 진짜 AI 파트는 혼자서도 돌아갑니다.

**갈래를 눌러서 고릅니다.** 낱말이 60가지라 한 화면에 다 펼치면 고르기 어렵습니다.
갈래를 먼저 누르면 그 안의 낱말 6개만 보입니다. **세 파트가 똑같은 방식**이라
한 번 익히면 다시 배울 게 없습니다.

「어떤」 칸 — 모습과 움직임을 고릅니다.

| 갈래 | 낱말 |
|---|---|
| 😊 기분 | 귀여운 · 웃는 · 예쁜 · 멋진 · 신난 · 졸린 |
| 🐘 크기 | 커다란 · 작은 · 뚱뚱한 · 길쭉한 · 둥근 · 뾰족한 |
| 🏃 움직임 | 달려가는 · 춤추는 · 나는 · 점프하는 · 구르는 · 걸어가는 |
| 😴 쉬기 | 자는 · 앉은 · 먹는 · 누워있는 · 노래하는 · 놀라는 |

> **색깔은 일부러 넣지 않았습니다.** 「빨간 고양이」는 결과가 뻔해서 그림이 크게 안 바뀝니다.
> 모습·움직임은 그림이 확 달라져서 **"내 말이 그림을 바꿨다"가 훨씬 잘 보입니다.**

「무엇을」 칸 —

| 갈래 | 낱말 |
|---|---|
| 🐱 동물 | 고양이 · 강아지 · 토끼 · 곰 · 펭귄 · 나비 |
| 🐦 하늘·바다 | 새 · 물고기 · 바다 · 무지개 · 별 · 비행기 |
| 🎂 먹을 것 | 케이크 · 딸기 · 수박 · 아이스크림 · 빵 · 사탕 |
| 🌸 자연 | 꽃 · 나무 · 눈사람 · 해바라기 · 단풍 · 선인장 |
| 🚗 탈것 | 자동차 · 기차 · 배 · 자전거 · 버스 · 로켓 |
| 🎈 물건 | 풍선 · 집 · 모자 · 공 · 시계 · 우산 |

> 「달려가는 케이크」처럼 **안 어울리는 조합도 막지 않습니다.** 진짜 AI는 그것도 그려 주고,
> 엉뚱한 그림이 나오는 편이 오히려 재미있습니다. 고르다 틀리는 일이 없어야 합니다.

> 갈래마다 **낱말 6개까지**입니다. 칸마다 세로 열이 하나씩 있고 그 안에 2개씩 3줄로
> 깔려서 딱 맞습니다. 하나만 더 넣으면 4줄이 되어 1024×600에서 잘립니다.
> 낱말을 더 넣고 싶으면 **갈래를 나누면** 됩니다(한 열에 갈래 4개까지 한 줄에 들어갑니다).

**칸마다 세로 열이 하나씩입니다.** 「어떤 | 무엇을 | 해 줘」가 나란히 서고, 각 열이 자기
갈래 탭과 낱말을 담습니다. 어느 탭이 어느 칸의 것인지 자리로 알 수 있고, 다 채운 칸은
초록 ✅로 바뀝니다.

**카드는 그림과 글자를 함께 둡니다.** 학생마다 읽기 수준 차이가 커서, 못 읽는 학생은 그림으로,
읽는 학생은 글자로 고릅니다. 누르면 음성으로도 읽어 줍니다.

**아무 순서로 눌러도 됩니다.** 카드마다 들어갈 자리가 정해져 있어서, 「그림 그려 줘」를 먼저
눌러도 「고양이」가 앞자리에 들어갑니다. 순서 때문에 틀리는 일이 없습니다.

> **복사는 눌러도 화면에 아무 일이 없어 보이는 게 가장 어려운 점입니다.** 그래서 문장이
> 클립보드 트레이(📋)로 **날아가 담기는 모습**을 보여 줍니다. 애니메이션을 꺼도
> 트레이가 초록으로 바뀌어 담긴 것이 남습니다.

> **붙여넣기는 진짜 클립보드를 읽지 않습니다.** 크롬이 권한 창을 띄우는데, 학생이 '차단'을
> 누르면 되돌리는 길이 주소창 자물쇠뿐이라 그 노트북이 그대로 막힙니다.
> 다만 **복사는 진짜로 합니다** — 마지막 파트에서 제미나이에 Ctrl+V로 붙여야 하기 때문입니다.

> **구글 계정 만들기는 앱에 넣지 않았습니다.** 구글이 가입 화면을 자주 바꿔서 앱 안내가
> 틀려지면 오히려 방해가 됩니다. 선생님이 실시간으로 직접 안내합니다(30분 이상, 휴대폰 저장까지).

마지막 파트에서 학생은 **진짜 제미나이 화면**을 만납니다. 그 화면은 앱이 손댈 수 없어
로그인이 풀리거나 안내 팝업이 뜰 수 있으므로, 보조 선생님이 그 구간을 봐 주셔야 합니다.
앱은 붙여넣었는지 확인할 수 없고, 확인하려 하지도 않습니다 — 「👍 해봤어요」 버튼 하나로
학생이 스스로 마무리합니다(「못 했어요」를 두면 그게 곧 실패 상태가 됩니다).

## 설계 원칙

- 실패 없음: "틀렸어요" 표시나 점수·감점 없이 부드러운 음성 안내로만 교정
  - 2차시 따라 쓰기의 빨간 글자는 "실패"가 아니라 **어디를 고치면 되는지 알려주는 표시**다.

- 정답 위치 랜덤 배제 — 매번 같은 순서라 교사가 미리 안내할 수 있고 학생도 예측할 수 있다

  모습·움직임이 그림을 확 바꿔서 "내 말이 그림을 바꿨다"가 훨씬 잘 보인다.

- **칸마다 세로 열을 하나씩** 준다(어떤 | 무엇을 | 해 줘). 처음엔 갈래 탭 9개를 한 줄에 늘어놓았는데
  **줄바꿈된 탭이 낱말 카드를 덮어썼다.** 열로 나누니 탭이 쌓여도 옆 칸을 침범하지 않는다
- **`.buildwrap.picking`** — 낱말을 고르는 동안엔 아직 못 쓰는 것들(빈 트레이·복사·다음)을 낮춰
  카드 6장이 다 보이게 한다. 3열이 되면서 카드가 한두 장만 보이던 문제를 이걸로 풀었다
- **한 화면만 재고 넘어갈 뻔했다** — 짧은 낱말 탭만 재고 통과시켰는데 긴 낱말 탭(`달려가는`)에서
  카드가 덮였다. 갈래마다 낱말 길이가 달라 넘침이 달라진다. 이후 **전 스텝 × 전 갈래 탭**을 훑도록 바꿨다
- 1366×768에서도 같은 문제가 있었다 — `picking` 규칙을 700 블록에만 넣었던 탓. 860 블록에도 넣었다
- 연습 AI의 답에 고른 말을 반영("네! 점프하는 곰 그림이에요") — 답이 늘 같으면 고른 의미가 없다
- 코드는 안 고쳤다. `SLOTS3` 배열을 추가하고 데이터만 늘렸다 (`sentenceText`/`isComplete`는 그대로)
- 1920×1080 / 1366×768 / 1024×600 × 전 13스텝 × 전 10갈래 넘침 0, 실제 클립보드 복사 확인
